Foundation: Understanding the Attack Surface

Active Directory Overview

Active Directory is a directory service developed by Microsoft for Windows domain networks. It authenticates and authorizes all users and computers in a Windows domain network, assigning and enforcing security policies for all computers and installing or updating software.

Key Components:

  • Domain Controller (DC): Server that responds to authentication requests
  • Kerberos: Authentication protocol (port 88)
  • LDAP: Directory access protocol (port 389)
  • SMB: File sharing protocol (port 445)
  • DNS: Name resolution (port 53)

/ PHASE 3 / TASK 3

Kerbrute: Stealthy User Enumeration

3.1 Understanding Kerbrute

Kerbrute performs user enumeration by exploiting Kerberos pre-authentication. When a username is submitted in a Kerberos AS-REQ request:

  • Valid user: Returns "KDC_ERR_PREAUTH_REQUIRED" (error 25) - user exists, needs password
  • Invalid user: Returns "KDC_ERR_C_PRINCIPAL_UNKNOWN" (error 6) - user doesn't exist

This method is stealthier than SMB enumeration because it doesn't trigger Windows event logs in the same way.

AS-REP Roasting: Cracking Kerberos Pre-Authentication

4.1 Theoretical Foundation

AS-REP roasting targets user accounts with the "Do not require Kerberos pre-authentication" flag enabled. Normally, when a user requests a Ticket Granting Ticket (TGT), they must prove their identity by encrypting a timestamp with their password hash. If pre-authentication is disabled, the Domain Controller will send an encrypted TGT without this proof, allowing an attacker to request and crack the encryption offline.

💡 SMB Protocol Deep Dive

SMB (Server Message Block) operates over port 445 (NetBIOS-less) or 139 (with NetBIOS). Modern Windows systems use SMB over port 445 exclusively. The protocol handles file operations, printer sharing, and inter-process communication via named pipes.

Important shares:

  • SYSVOL: Contains group policies and logon scripts - often contains passwords
  • NETLOGON: Domain logon scripts
  • IPC$: Named pipes for RPC - used by tools like secretsdump
/ PHASE 6 / TASK 7

Secretsdump: Extracting Domain Hashes

6.1 Understanding Secretsdump

Impacket's secretsdump.py implements the DRSUAPI protocol, which allows domain replication. By simulating a Domain Controller replication request, it can request all password hashes from the NTDS.dit file. This requires privileged credentials - exactly what we have with the backup account.

6.2 Running Secretsdump

# Basic secretsdump command
~/.local/bin/secretsdump.py spookysec.local/backup:backup2517860@10.48.165.142

# Save output to file
~/.local/bin/secretsdump.py spookysec.local/backup:backup2517860@10.48.165.142 > secretsdump.txt

# If you have the hash instead of password
~/.local/bin/secretsdump.py -hashes aad3b435b51404eeaad3b435b51404ee:HASH_VALUE spookysec.local/backup@10.48.165.142

6.3 Understanding Secretsdump Output

The output contains several sections:

[*] Target system bootKey: 0x...
[*] Dumping local SAM hashes (local accounts)
[*] Dumping domain hashes (domain accounts)
[*] Dumping LSA secrets (service account passwords)
[*] Dumping cached domain logon information (previous logons)

Domain hash format:

username:rid:lmhash:nthash:::
Example:
Administrator:500:aad3b435b51404eeaad3b435b51404ee:5f4dcc3b5aa765d61d8327deb882cf99:::

6.4 Extracting Administrator's NTLM Hash

# Search for Administrator in output
grep -i "administrator" secretsdump.txt

# Extract just the NTLM hash
grep "Administrator" secretsdump.txt | cut -d ':' -f4

# Save to file for later use
grep "Administrator" secretsdump.txt | cut -d ':' -f4 > admin_hash.txt

6.5 Task 7 Answer

Q4: What is the NTLM hash of the Administrator account?
Answer: The 32-character hex string after the colons (e.g., 0e0363213e37b94221497260b0bcb4fc)
🔬 Technical Deep Dive: DRSUAPI

The Directory Replication Service (DRS) Remote Protocol (DRSUAPI) is used to replicate Active Directory data between Domain Controllers. By calling the IDL_DRSGetNCChanges function, a client can request changes from the DC, including password hashes. This is the same mechanism used by legitimate DCs for replication, making it difficult to detect as malicious.

Windows event ID 4662 (An operation was performed on an object) may be triggered, but in many environments, replication events are considered normal.

/ PHASE 7 / TASKS 8-9

Pass-the-Hash: Gaining Shell Access

7.1 Pass-the-Hash Theory

Pass-the-Hash (PtH) is an attack technique where an attacker uses the NTLM hash of a user's password to authenticate to remote systems, without needing the plaintext password. This works because NTLM authentication uses the hash directly in the challenge-response process.

7.2 Using psexec.py

🖥️ Tool Comparison

psexec.py: Uploads a service binary to ADMIN$ share and runs it via Service Control Manager. Creates services, which may be more detectable.

wmiexec.py: Uses Windows Management Instrumentation for semi-interactive shells. No file upload required, but less interactive.

smbexec.py: Similar to psexec but uses a different named pipe. Creates a service but cleans up after itself.

atexec.py: Creates scheduled tasks to execute commands. Minimal footprint but one-off commands.
