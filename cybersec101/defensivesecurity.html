Introduction

Offensive security gets the spotlight—finding bugs, breaking things, capturing flags. But defensive security is what keeps organizations running. This guide covers the core concepts of defensive security: the five essential tasks every defender performs, the role of a Security Operations Center (SOC), threat intelligence, digital forensics, incident response, malware analysis, and how defense in depth applies to threat intelligence.

Whether you're preparing for the TryHackMe Defensive Security Intro room or building a foundation in blue team operations, this is your starting point.

1. The Five Core Defensive Tasks

Before diving into SOC and DFIR, understand the foundational tasks that every defensive security program relies on.

User Cyber Security Awareness

Training users to recognize phishing, use strong passwords, and report incidents. Users are the primary entry point—the majority of attacks begin with phishing.

Documenting and Managing Assets

You cannot protect what you do not know exists. Inventory all hardware, software, cloud services, and data assets.

Updating and Patching Systems

Attackers exploit known vulnerabilities. Regular patching closes the door. CVSS scores help prioritize critical fixes.

Preventative Security Devices

Firewalls control traffic. Intrusion Prevention Systems (IPS) block malicious activity in real-time based on signatures and rules.

Logging and Monitoring

If you do not log it, you cannot detect it. SIEM aggregation and 24/7 monitoring are essential for detection.

2. Security Operations Center (SOC)

A SOC is a team of cybersecurity professionals monitoring the network 24/7 to detect malicious activity. They do not always fix issues—they detect, triage, and escalate.

The Four Pillars of SOC Monitoring

Category What It Means Detection Method
Vulnerabilities Weaknesses that could be exploited Vulnerability scanners, threat feeds
Policy Violations Users breaking security rules DLP, web proxies, email filters
Unauthorized Activity Stolen credentials used by attackers Geolocation anomalies, impossible travel, beaconing
Network Intrusions Active exploitation in progress IDS/IPS signatures, SIEM correlation, EDR alerts
SOC Alert Triage Flow
    Raw Logs → SIEM Correlation → Alert Generated → Analyst Review

3. Threat Intelligence

Definition: Actionable knowledge about adversaries—who they are, what they want, how they operate.

Key Distinction: Intelligence is not data. Data is raw logs. Intelligence is processed, analyzed, and actionable.

Adversary Types

Adversary Motivation Target Example
Nation-statePolitical advantage, espionageGovernment, critical infrastructure
Ransomware groupFinancial profitHospitals, corporations, schools
HacktivistIdeological statementOrganizations they oppose
Insider threatRevenge, financial gainTheir own employer
CybercriminalFinancial fraudBanks, e-commerce

TTPs (Tactics, Techniques, Procedures)

TermDefinitionExample
TacticAdversary's goalInitial access, persistence, privilege escalation
TechniqueHow they achieve itPhishing, exploiting public-facing application
ProcedureSpecific implementationSpear-phishing with COVID-19 themed PDF

Why TTPs matter: IOCs (IPs, domains) change daily. TTPs change slowly. Understanding how an adversary operates enables detection even when infrastructure changes.

Indicator of Compromise (IOC)

Definition: An Indicator of Compromise is a piece of forensic evidence that suggests a system has been compromised or is currently under attack. IOCs are the "digital breadcrumbs" left behind by adversaries during their operations.

Common Types of IOCs:

TypeExamplesWhat It Reveals
NetworkIP addresses, domain names, URLs, DNS queriesCommand & control servers
FileFile hashes (MD5, SHA1, SHA256), file names, pathsSpecific malicious files to hunt for
BehavioralRegistry keys, process names, scheduled tasksHow malware persists on a system
EmailSender addresses, subject lines, attachment namesPhishing campaign indicators
MemoryProcess injection patterns, API call sequencesIn-memory-only attacks (fileless malware)

IOC vs TTP:

IOCTTP
What it isEvidence of compromiseAdversary behavior
StabilityChanges quickly (attackers rotate infrastructure)Changes slowly (how they operate)
UseDetect known threatsHunt for unknown threats
ExampleIP 185.130.5.253Spear-phishing with password-protected ZIP attachments

IOC Lifecycle:

StageDescription
DiscoveryIOC identified through malware analysis, threat hunting, or external intelligence
ValidationVerified against multiple sources; false positives eliminated
OperationalizationPushed to security controls (firewalls, EDR, SIEM)
DetectionAlerts triggered when IOC is observed
ResponseIncident response initiated
RetirementIOC removed when no longer relevant

Why IOCs Matter: IOCs enable detection, historical hunting, prevention through blocking, and sharing with the community. However, they have limitations: short shelf life, lack of context, evadable by polymorphic malware, and reactive nature. This is why TTPs are equally important.

4. Defense in Depth in Threat Intelligence

Defense in Depth is the strategy of using multiple, overlapping layers of security so that if one layer fails, others still protect the asset. No single control is perfect. This principle applies directly to threat intelligence across collection, analysis, and operationalization.

Layer 1: Collection Sources (Multiple Feeds)

No single intelligence source is complete or trustworthy. Defense in Depth requires pulling from diverse, overlapping sources.

LayerSource TypeExamples
InternalYour own telemetryFirewall logs, DNS queries, endpoint detection, proxy logs
CommercialPaid threat feedsRecorded Future, CrowdStrike, VirusTotal Enterprise
Open SourceOSINTAbuseIPDB, AlienVault OTX, MISP communities, security researchers
Information SharingSector-specificISACs (FS-ISAC for finance, MS-ISAC for government)
HoneypotsYour own sensorsSystems designed to attract attackers, revealing TTPs

Why multiple sources matter: One feed misses a new IOC. Another feed flags false positives. Internal logs confirm whether intelligence is relevant to your environment.

Layer 2: Intelligence Analysis (Multiple Validation)

Raw intelligence must be analyzed through multiple lenses before becoming actionable.

LayerPurpose
Confidence ScoringIs this IOC from a reliable source? How many independent sources confirm it?
Context EnrichmentDoes this IP belong to a known threat group? What TTPs are associated?
Relevance FilteringDoes this threat target our industry, geography, or technology stack?
False Positive ScreeningIs this actually legitimate traffic misidentified?

Defense in Depth here: No single analyst or tool makes the call. Intelligence is validated through cross-referencing multiple feeds, sandbox verification, and threat hunting to confirm presence before alerting.

Layer 3: Operationalization (Multiple Detection Layers)

Threat intelligence feeds into multiple defensive layers—pure Defense in Depth.

Defensive LayerHow Intelligence Is Applied
NetworkBlock IOCs (IPs, domains) at firewall; update IPS signatures; sinkhole malicious DNS
EndpointHunt for IOCs across endpoints; update EDR detection rules; isolate compromised hosts
IdentityDetect login attempts from malicious IPs; flag impossible travel patterns
EmailBlock sender domains/addresses; detonate attachments in sandbox

Why This Matters: The Attacker's View

Attackers know defenders use multiple layers. They design operations to evade any single control.

Attacker TacticEvadesBut Gets Caught By
Use encrypted trafficNetwork signature detectionEndpoint behavior analysis
Use legitimate credentialsNetwork perimeter controlsIdentity anomaly detection
Live-off-the-land toolsAV signaturesEDR behavioral rules, logging
Rotate infrastructureStatic IOC blocksTTP-based hunting

Key takeaway: Defense in Depth with threat intelligence means even if an attacker evades the firewall block, they still trigger endpoint detection. Even if they evade endpoint, they trigger identity alerts. Each layer provides independent protection.

5. Digital Forensics and Incident Response (DFIR)

Digital Forensics

Definition: The application of science to investigate crimes and establish facts using digital evidence.

Four Forensic Disciplines

DisciplineWhat It AnalyzesWhat It Reveals
File SystemForensic image of storageInstalled programs, created files, deleted files
MemoryRAM capture (volatile)Running processes, network connections, injected code
System LogsWindows Event Logs, syslogUser logins, process executions, system changes
Network LogsPCAP, flow dataC2 communication, data exfiltration, lateral movement

Key Principle: "The artifact never lies. The question is whether you found it."

Incident Response

Definition: Methodology for handling cyber attacks—reduce damage, recover quickly.

Incident Response Framework (SANS PICERL)

PreparationBuild IR team, develop runbooks, stock toolsBe ready before incident occurs
Detection & AnalysisDetect via SIEM, validate, scope impactUnderstand what you are dealing with
ContainmentShort-term: disconnect, block IPs. Long-term: build clean systemsStop the bleeding
EradicationRemove malware, backdoors, persistenceEliminate attacker presence
RecoveryRestore from clean backups, monitorReturn to normal operations
Lessons LearnedRoot cause analysis, update controlsImprove for next time
Incident Response Flow with Feedback Loop
    Preparation → Detection → Analysis → Containment → Eradication → Recovery → Lessons Learned

6. Malware Analysis

Definition: Examining malicious software to understand its behavior and impact.

Common Malware Types

VirusSelf-replicating code attached to programsAlters, overwrites, deletes files; spreads
Trojan HorseDisguised as legitimate softwareShows desirable function, hides malicious one
RansomwareEncrypts user filesDemands payment for decryption key

Analysis Approaches

Static AnalysisExamine without executingSafe, no riskMisses runtime behavior, obfuscated code
Dynamic AnalysisRun in sandbox, monitor behaviorShows real activityMalware may detect sandbox
Malware Analysis Outputs
    Malware Sample → Analysis → Outputs:
                                  ├── IOCs (IPs, domains, hashes) → Feed to SOC
                                  ├── Behavioral description → Understand impact
                                  ├── Detection signatures → Update AV/IPS
                                  └── Recovery guidance → Remove and restore

Key Takeaway: SOC and DFIR are not separate silos. SOC detects. DFIR investigates and creates intelligence that makes SOC smarter. Each incident improves the next detection. Defense in Depth ensures that even if one layer fails, others remain effective.
